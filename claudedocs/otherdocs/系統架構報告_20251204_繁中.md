## 1. 系統概況與總覽

### 1.1 什麼是 DocAI？

**DocAI** 是一個本地端的 **RAG（檢索增強生成）** 系統。可以把它想像成你的私人圖書管理員，不僅知道每本書存放在哪裡，還能閱讀、理解並回答有關它們的問題。

**類比**：想像一個巨大的圖書館，其中：
- 你上傳文件（書籍）到圖書館
- 圖書管理員（DocAI）閱讀並索引每一頁
- 當你提出問題時，圖書管理員會找到最相關的段落
- 然後，AI 助手閱讀這些段落並制定答案

### 1.2 雙 RAG 架構

DocAI 實作了**兩個獨立運作的平行系統**：

```
┌─────────────────────────────────────────────────────────────┐
│                       DocAI 系統                             │
├─────────────────────────┬───────────────────────────────────┤
│   檔案型 RAG             │       技能型 RAG                   │
│   (舊系統)               │       (新架構)                     │
├─────────────────────────┼───────────────────────────────────┤
│ • 每個檔案獨立索引        │ • 精選知識領域                     │
│ • Milvus 向量儲存        │ • FAISS 向量儲存                   │
│ • 5 階段 OPMP 流程       │ • 簡化查詢流程                     │
│ • SSE 串流              │ • JSON 回應                        │
│ • 多檔案選擇             │ • 多技能選擇                       │
└─────────────────────────┴───────────────────────────────────┘
```

**檔案型 RAG** = 個別 PDF 檔案，可分別搜尋
**技能型 RAG** = 精選的「技能」（知識領域）結合多個 PDF

### 1.3 技術堆疊

| 元件 | 技術 | 用途 |
|-----------|------------|---------|
| **後端** | Python 3.11, FastAPI | API 伺服器，非同步處理 |
| **向量資料庫（檔案）** | Milvus | 高效能向量搜尋 |
| **向量資料庫（技能）** | FAISS | 輕量級，物理隔離的索引 |
| **中繼資料庫** | SQLite | 技能中繼資料，關聯 |
| **嵌入模型** | BAAI/bge-m3 | 1024 維文字嵌入 |
| **LLM** | Ollama（本地）/ OpenAI | 回應生成 |
| **前端** | Vanilla JS + Jinja2 | 使用者介面 |

## 2. 資料流與工作流程分析

### 2.1 文件上傳流程（技能型）

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  使用者       │     │  API 層      │     │  服務層      │
│  上傳 PDF    │────▶│  skills.py   │────▶│  Ingestion   │
└──────────────┘     └──────────────┘     └──────────────┘
                                                │
                     ┌──────────────────────────┴───────────────┐
                     ▼                                          ▼
              ┌──────────────┐                           ┌──────────────┐
              │  PDF 提取    │                           │  分塊        │
              │  (PyPDF2)    │                           │  (1000 字元) │
              └──────────────┘                           └──────────────┘
                     │                                          │
                     └──────────────────────────┬───────────────┘
                                                ▼
                                         ┌──────────────┐
                                         │  嵌入        │
                                         │  (BGE-M3)    │
                                         └──────────────┘
                                                │
                     ┌──────────────────────────┴───────────────┐
                     ▼                                          ▼
              ┌──────────────┐                           ┌──────────────┐
              │  FAISS 儲存  │                           │  SQLite      │
              │  (向量)      │                           │  (中繼資料)  │
              └──────────────┘                           └──────────────┘
```

**逐步說明**：

1. **上傳**：使用者透過 `/api/v1/skills/{skill_name}/upload-source` 提交 PDF
2. **儲存**：PDF 儲存至 `data/pdf_sources/{skill_name}/`
3. **提取**：PyPDF2 從每頁提取文字
4. **分塊**：文字分割成約 1000 字元的塊，並有重疊
5. **嵌入**：BGE-M3 為每個塊生成 1024 維向量
6. **儲存向量**：FAISS 索引儲存至 `data/faiss_indices/skills/{skill_id}/`
7. **儲存中繼資料**：SQLite 記錄技能資訊、塊數量

### 2.2 查詢流程（RAG 流程）

```
┌────────────┐     ┌────────────┐     ┌────────────┐     ┌────────────┐
│   使用者   │     │   查詢     │     │  向量      │     │  上下文    │
│   查詢     │────▶│   嵌入     │────▶│  搜尋      │────▶│  組裝      │
└────────────┘     └────────────┘     └────────────┘     └────────────┘
                                                                │
                                                                ▼
                   ┌────────────┐     ┌────────────┐     ┌────────────┐
                   │   答案     │◀────│   LLM      │◀────│   提示     │
                   │   顯示     │     │  生成      │     │  建構      │
                   └────────────┘     └────────────┘     └────────────┘
```

**逐步說明**：

1. **使用者查詢**：「什麼是機器學習？」
2. **查詢嵌入**：BGE-M3 將查詢轉換為 1024 維向量
3. **向量搜尋**：FAISS 找到前 K 個相似塊（預設 K=10）
4. **上下文組裝**：檢索到的塊格式化為上下文
5. **提示建構**：系統提示 + 上下文 + 使用者查詢組合
6. **LLM 生成**：Ollama/OpenAI 生成回應
7. **回應**：返回答案並附上來源引用

### 2.3 skill_heads 架構（單一真相來源）

新的 `skill_heads` 表解決了**雙真相來源**的反模式：

```
┌─────────────────────────────────────────────────────────────┐
│                    skill_heads 表                            │
│            (技能定義 - 單一來源)                              │
├─────────────────────────────────────────────────────────────┤
│  head_id        │ skill_name │ description │ category       │
│─────────────────┼────────────┼─────────────┼────────────────│
│  head_llm_001   │ 大語言模型大全 │ LLM 知識庫   │ AI             │
│  head_invest_02 │ 投資理財      │ 理財知識     │ Finance        │
└─────────────────────────────────────────────────────────────┘
                              │
                              │ 1:N 關係
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   skill_metadata 表                          │
│                  (文件記錄)                                   │
├─────────────────────────────────────────────────────────────┤
│  skill_id       │ head_id       │ source_name │ total_chunks │
│─────────────────┼───────────────┼─────────────┼──────────────│
│  skill_001_src0 │ head_llm_001  │ LLM_Book.pdf│ 883          │
│  skill_001_src1 │ head_llm_001  │ GPT_Guide   │ 385          │
│  skill_002_src0 │ head_invest_02│ Finance.pdf │ 533          │
└─────────────────────────────────────────────────────────────┘
```

**為什麼採用這種設計？**
- **之前**：skill_config.json + skill_metadata.db = 同步問題
- **之後**：skill_heads 表 = 單一真相來源
- **好處**：創建新技能會自動在 UI 中創建可見的標題

```python
class SkillQueryService:
    async def process_query(
        self,
        query: str,
        skill_names: List[str],
        top_k: int = 10
    ) -> QueryResult:
        # 1. 嵌入查詢
        query_vector = embedding_provider.embed_query(query)
        
        # 2. 跨所有選定技能搜尋
        results = []
        for skill in skill_names:
            chunks = vector_provider.search(
                skill_id=skill,
                vector=query_vector,
                top_k=top_k
            )
            results.extend(chunks)
        
        # 3. 重新排序並取前 K 個
        results = rerank(results)[:top_k]
        
        # 4. 建構提示
        context = format_context(results)
        prompt = build_prompt(query, context)
        
        # 5. 生成回應
        answer = llm_provider.generate(prompt)
        
        return QueryResult(
            answer=answer,
            sources=results
        )
```

#### app/Providers/vector_store.py
**職責**：向量搜尋抽象

**FAISS 實作**：
```python
class FaissVectorStore:
    def __init__(self, base_dir: str):
        self.indices = {}  # 載入的索引快取
    
    def save_index(self, skill_id: str, vectors: np.ndarray):
        # 創建 FAISS 索引（IndexFlatIP 用於內積）
        index = faiss.IndexFlatIP(1024)
        index.add(vectors)
        
        # 儲存至磁碟
        path = f"{base_dir}/skills/{skill_id}/index.faiss"
        faiss.write_index(index, path)
    
    def similarity_search(
        self,
        skill_id: str,
        query_vector: np.ndarray,
        top_k: int
    ) -> List[VectorSearchResult]:
        # 載入索引（如果尚未載入）
        index = self._load_index(skill_id)
        
        # 執行相似度搜尋
        scores, indices = index.search(query_vector, top_k)
        
        # 從 SQLite 載入中繼資料
        chunks = metadata_provider.get_chunks_by_indices(
            skill_id, indices
        )
        
        return [
            VectorSearchResult(
                content=chunk.text,
                score=score,
                metadata=chunk.metadata
            )
            for chunk, score in zip(chunks, scores)
        ]
```

**為什麼選擇 FAISS？**
- 無需伺服器（不像 Milvus）
- 純檔案儲存（適合本地部署）
- 快速的內存中搜尋
- 物理隔離的索引（每個技能一個目錄）

## 4. 類別層級設計

### 4.1 服務類別層次結構

```
AbstractRetrievalService (抽象基類)
│
├── FileBasedRetrievalService (舊系統)
│   ├── 使用 Milvus
│   ├── OPMP 5 階段流程
│   └── 每個檔案獨立索引
│
└── SkillBasedRetrievalService (新系統)
    ├── 使用 FAISS
    ├── 簡化流程
    └── 跨來源的合併索引
```

**抽象方法**：
```python
class AbstractRetrievalService(ABC):
    @abstractmethod
    async def retrieve_context(
        self,
        query: str,
        target_ids: List[str],  # 檔案 ID 或技能名稱
        top_k: int
    ) -> List[RetrievedChunk]:
        """檢索與查詢相關的上下文塊"""
        pass
    
    @abstractmethod
    async def ingest_document(
        self,
        document_path: str,
        metadata: Dict
    ) -> IngestionResult:
        """攝取新文件到系統"""
        pass
```

**策略模式好處**：
- 可以在不影響 API 的情況下切換檢索策略
- 兩個系統共享相同的介面
- 輕鬆進行 A/B 測試（檔案型 vs 技能型）

```python
    skill_names: List[str],
    top_k: int = 10,
    enable_rerank: bool = True
) -> QueryResult:
    """
    處理使用者對多個技能的查詢

    2. 跨所有選定技能並行搜尋
```

##### _multi_skill_search()
```python
async def _multi_skill_search(
    self,
    query_vector: np.ndarray,
    skill_names: List[str],
    top_k: int
) -> List[RetrievedChunk]:
    """
    跨多個技能執行向量搜尋
    
    策略：
    1. 為每個技能檢索 top_k 個結果
    2. 將所有結果合併到單一清單
    3. 按分數排序
    4. 取前 top_k 個整體結果
    
    這確保沒有單一技能主導結果
    """
    all_results = []
    for skill in skill_names:
        results = await self.vector_provider.search(
            skill_id=skill,
            vector=query_vector,
            top_k=top_k
        )
        all_results.extend(results)
    
    # 按分數排序並取前 K 個
    all_results.sort(key=lambda x: x.score, reverse=True)
    return all_results[:top_k]
```

```python
def split_text(text: str) -> List[str]:
    """
    遞迴文字分割器
```

### 5.2 嵌入生成函式

**函式**：`EmbeddingProvider.embed_batch()`

**實作**（BGE-M3）：
```python
async def embed_batch(
    self,
    texts: List[str],
    batch_size: int = 32
) -> np.ndarray:
    """
    將文字清單轉換為嵌入向量
    
    流程：
    1. 將輸入分批（避免記憶體爆炸）
    2. 為每個批次：
       a. 對文字進行標記化
       b. 通過 BERT 模型傳遞
       c. 提取 [CLS] 標記嵌入
       d. 正規化向量（L2 正規化）
    3. 將所有批次連接成單一陣列
    
    返回：形狀為 (n_texts, 1024) 的 numpy 陣列
    """
    all_embeddings = []
    
    for i in range(0, len(texts), batch_size):
        batch = texts[i:i+batch_size]
        
        # 標記化
        inputs = self.tokenizer(
            batch,
            padding=True,
            truncation=True,
            max_length=512,
            return_tensors="pt"
        )
        
        # 推理
        with torch.no_grad():
            outputs = self.model(**inputs)
        
        # 提取 [CLS] 嵌入並正規化
        embeddings = outputs.last_hidden_state[:, 0, :]
        embeddings = F.normalize(embeddings, p=2, dim=1)
        
        all_embeddings.append(embeddings.cpu().numpy())
    
    return np.vstack(all_embeddings)
```

**為什麼選擇 BGE-M3？**
- 多語言（中文 + 英文）
- 1024 維（平衡大小與品質）
- SOTA 檢索效能

### 5.3 FAISS 索引建立

**函式**：`VectorStoreProvider.create_index()`

**實作**：
```python
def create_index(
    self,
    skill_id: str,
    vectors: np.ndarray
) -> None:
    """
    為技能創建 FAISS 索引
    
    流程：
    1. 正規化向量（確保單位長度）
    2. 創建內積索引（IndexFlatIP）
    3. 添加向量到索引
    4. 將索引保存到磁碟
    
    索引類型：IndexFlatIP
    - 平面索引（無壓縮）
    - 內積相似度（餘弦相似度用於正規化向量）
    - 精確搜尋（無近似）
    """
    # 正規化向量
    faiss.normalize_L2(vectors)
    
    # 創建索引
    dimension = vectors.shape[1]  # 1024
    index = faiss.IndexFlatIP(dimension)
    
    # 添加向量
    index.add(vectors)
    
    # 保存到磁碟
    index_path = f"{self.base_dir}/skills/{skill_id}/index.faiss"
    os.makedirs(os.path.dirname(index_path), exist_ok=True)
    faiss.write_index(index, index_path)
```

**索引類型比較**：

| 類型 | 速度 | 準確度 | 記憶體 | 使用情境 |
|------|------|--------|--------|----------|
| **IndexFlatIP** | 慢 | 完美 | 高 | <100K 向量 |
| IndexIVFFlat | 中 | ~99% | 中 | 100K-1M 向量 |
| IndexHNSW | 快 | ~95% | 非常高 | >1M 向量 |

**DocAI 選擇 IndexFlatIP 的原因**：
- 每個技能的向量少於 50K
- 準確度比速度更重要
- 簡單（無訓練需求）

### 5.4 相似度搜尋函式

**函式**：`VectorStoreProvider.similarity_search()`

**實作**：
```python
async def similarity_search(
    self,
    skill_id: str,
    query_vector: np.ndarray,
    top_k: int = 10
) -> List[VectorSearchResult]:
    """
    在 FAISS 索引中執行相似度搜尋
    
    流程：
    1. 載入索引（如果尚未快取）
    2. 正規化查詢向量
    3. 執行內積搜尋
    4. 從 SQLite 檢索塊中繼資料
    5. 組合向量分數 + 文字內容
    
    返回：前 K 個最相似的塊
    """
    # 載入索引
    index = self._load_or_cache_index(skill_id)
    
    # 正規化查詢
    query_vector = query_vector.reshape(1, -1)
    faiss.normalize_L2(query_vector)
    
    # 搜尋
    scores, indices = index.search(query_vector, top_k)
    
    # 獲取中繼資料
    chunks = self.metadata_provider.get_chunks_by_indices(
        skill_id, indices[0]
    )
    
    # 組合結果
    results = []
    for chunk, score in zip(chunks, scores[0]):
        results.append(VectorSearchResult(
            content=chunk.text_content,
            score=float(score),
            metadata={
                "skill_id": skill_id,
                "chunk_index": chunk.chunk_index,
                "page_number": chunk.page_number,
                "source": chunk.source_name
            }
        ))
    
    return results
```

**效能優化**：
```python
# 索引快取（避免重複載入）
self._index_cache: Dict[str, faiss.Index] = {}

def _load_or_cache_index(self, skill_id: str):
    if skill_id not in self._index_cache:
        path = f"{self.base_dir}/skills/{skill_id}/index.faiss"
        self._index_cache[skill_id] = faiss.read_index(path)
    return self._index_cache[skill_id]
```

### 5.5 提示建構函式

**函式**：`PromptBuilder.build_rag_prompt()`

**實作**：
```python
def build_rag_prompt(
    query: str,
    retrieved_chunks: List[RetrievedChunk],
    system_prompt: str = None
) -> str:
    """
    為 LLM 建構 RAG 提示
    
    範本結構：
    ===
    系統：{system_prompt}
    
    上下文：
    [來源 1: {source_name}, 頁 {page}]
    {chunk_content}
    
    [來源 2: ...]
    ...
    
    問題：{query}
    
    說明：根據上下文回答問題。包含來源引用。
    ===
    """
    if system_prompt is None:
        system_prompt = (
            "你是一個樂於助人的助手，根據提供的上下文回答問題。"
            "如果上下文不包含答案，請誠實地說明。"
            "包含來源引用以支持你的答案。"
        )
    
    # 格式化上下文塊
    context_parts = []
    for i, chunk in enumerate(retrieved_chunks, 1):
        context_parts.append(
            f"[來源 {i}: {chunk.metadata['source']}, "
            f"頁 {chunk.metadata.get('page_number', 'N/A')}]\n"
            f"{chunk.content}\n"
        )
    
    context = "\n".join(context_parts)
    
    # 組裝最終提示
    prompt = f"""系統：{system_prompt}

上下文：
{context}

問題：{query}

說明：根據上述上下文回答問題。包含來源引用。"""
    
    return prompt
```

## 7. 總結

### 7.1 架構亮點

1. **雙 RAG 系統**：檔案型（Milvus）和技能型（FAISS）獨立運作
2. **分層架構**：端點 → 服務 → 提供者 → 儲存
3. **單一真相來源**：`skill_heads` 表取代 JSON 配置
4. **物理隔離**：檔案型與技能型索引的獨立目錄

### 7.2 關鍵設計模式

| 模式 | 實作 | 好處 |
|---------|----------------|---------|
| **儲存庫** | 提供者（VectorStore、Metadata） | 資料庫抽象 |
| **策略** | AbstractRetrievalService | 可交換的檢索模式 |
| **工廠** | `get_*_provider()` 函式 | 單例管理 |
| **TypedDict vs Pydantic** | 內部 vs 外部 | 效能 vs 驗證 |

### 7.3 資料流程總結

```
上傳：  PDF → 提取 → 分塊 → 嵌入 → FAISS + SQLite
查詢：  問題 → 嵌入 → 搜尋 → 上下文 → LLM → 答案
```

### 7.4 技術選擇理由

| 選擇 | 為什麼 |
|--------|-----|
