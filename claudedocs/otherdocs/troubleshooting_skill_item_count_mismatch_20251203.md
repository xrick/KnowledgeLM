## 2. 根本原因分析

### 2.1 數據架構差異

**skill/config 頁面**：
- 直接讀取 `scripts/skill_data/skill_config.json`
- 顯示配置中定義的 9 個 PDF sources
- 每個 PDF 作為獨立項目顯示

**skill/chat 頁面**：
- 讀取 SQLite `data/skill_metadata.db`
- 使用 `groupSkillsByName()` 函數進行分組
- 只顯示資料庫中存在的條目

### 2.2 OLD 架構問題

「大語言模型大全」原本使用 **OLD 合併架構** 建立：

```
OLD Architecture (Merged):
├── skill_20251126_105138_b8cc08c1 (Main, 883 chunks)
│   ├── 合併了 5 個 refData/rawdata/LLM/*.pdf
│   └── source_name = NULL ❌
├── skill_20251127_100500_b8cc08c1 (Instant, 385 chunks)
├── skill_20251128_030424_b8cc08c1 (Instant, 264 chunks)
└── skill_20251128_070013_b8cc08c1 (Instant, 311 chunks)
```

**問題**：
1. 原始 5 個 PDF 被合併為 1 個索引 (883 chunks)
2. 所有條目的 `source_name = NULL`
3. 無法識別來源文件名稱
4. Chat 頁面只顯示 4 個條目（1 main + 3 instant）

## 6. 附加修復：Delete-Unfold Bug

### 問題
在 skill/config 頁面刪除項目時，skill group 會意外收起，需要重新展開才能繼續刪除。

### 原因
`removeSource()` → `loadConfig()` → `renderSkills()` 會重新生成 HTML，導致 `.expanded` CSS class 丟失。

### 修復
在 `template/skill_config.html` 的 `renderSkills()` 函數中加入狀態保存/恢復邏輯：

```javascript
// 保存展開狀態 (渲染前)
const expandedSkillNames = new Set();
container.querySelectorAll('.skill-card.expanded').forEach(card => {
    const skillName = card.getAttribute('data-skill-name');
    if (skillName) expandedSkillNames.add(skillName);
});

// ... 渲染邏輯 ...

// 恢復展開狀態 (渲染後)
container.querySelectorAll('.skill-card').forEach(card => {
    const skillName = card.getAttribute('data-skill-name');
    if (skillName && expandedSkillNames.has(skillName)) {
        card.classList.add('expanded');
    }
});
```

## 9. 結論

1. 配置文件中的 9 個 PDF 被合併為 1 個索引
