Phase 3: 智能重建系統 ✅
後端架構:
SmartRebuildStrategy 類 (~95 行):
├─ 3 種重建範圍:
│  ├─ NONE: 無需重建（<threshold）
│  ├─ TARGETED: 只重建受影響的 skills
│  └─ ALL: 重建所有 skills
│
├─ determine_rebuild_scope()
│  ├─ 檢查臨時附件數
│  ├─ 與 rebuild_threshold 比較
│  └─ 返回 (scope, affected_skills_list)
│
└─ should_clear_attachments_after_rebuild()
   └─ 確定重建後是否清除臨時附件
rebuild_from_config.py 增強:
修改 rebuild_all() 方法支援 3 個新參數:
force_all: 強制重建所有 skills
use_smart_strategy: 啟用智能策略
返回值改為 (results, rebuild_scope) 元組
支援環境變數:
SMART_REBUILD: 啟用/禁用智能策略
FORCE_ALL: 強制重建全部
API 端點增強 (/api/v1/skills/rebuild):
RebuildRequest 新增欄位:
use_smart_strategy (default: true)
force_all (default: false)
實現自動清理邏輯:
檢查重建是否實際發生
只有在有目標重建或全量重建後清除附件
改用 Python 直接執行（而非 shell 腳本）以便更好的控制
前端改進 (UI):
增強重建確認對話框:
顯示臨時附件數 vs 閾值
顯示 Skills 總數
提示智能模式的行為
自動清理臨時附件的說明
工作流程邏輯:
用戶新增臨時附件
  ↓
累積到 5 個（預設閾值）
  ↓
觸發 "Rebuild Skills"
  ↓
智能策略判斷:
  ├─ 如果 < 5: 等待更多，不重建
  ├─ 如果 ≥ 5: 只重建受影響的 skills
  └─ 完成後自動清除臨時附件
