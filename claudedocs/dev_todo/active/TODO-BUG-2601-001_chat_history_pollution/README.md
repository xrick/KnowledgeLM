## 📝 內容描述

### 背景說明

用戶在 Skill Chat 頁面操作時發現：切換到新 Skill 後，系統回覆中出現「已在前面回答」的訊息，表明 LLM 看到了不應該存在的歷史對話。

**問題重現步驟**:
1. 選擇 A Skill（例如：MSI Product）
2. 輸入提示：「請總結所有文件內容」
3. 系統正常回覆
4. 切換到 B Skill（例如：投資理財）
5. 輸入相同提示：「請總結所有文件內容」
6. **異常回覆**：「目前對話中只有關於投資目的的資訊，已在前面回答」

### 根本原因

MongoDB 中的 chat_history 是跨 session 持久化的。當用戶返回同一個 Skill 時，之前的對話會被重新載入並影響 LLM 的回答。

### 目標

- 修復切換 Skill 時的聊天歷史污染問題
- 確保每個 Skill 的對話完全獨立
- 提供用戶選擇是否繼續或清空歷史對話的機制

### 範圍

- **包含**:
  - 前端切換 Skill 時的處理邏輯
  - MongoDB session 清空機制
  - 用戶確認對話框 UI

- **不包含**:
  - 「建立新對話」功能（另案處理）
  - Session 資料模型重構
