## 4. 回滾指令速查表

### 情境 A: 全部撤銷，回到修改前

放棄所有修改，切回原始分支：

```bash
git checkout docai_dev_excel_2026_linux
```

原始分支始終停在 `bee74a8`，不受 feature branch 的任何修改影響。

### 情境 B: 撤銷 feature branch 上最後一個 commit

保留其他修改，僅撤銷最近一次提交：

```bash
git revert HEAD
```

### 情境 C: 撤銷特定 Phase 的 commit

精確回滾某一個階段的修改（保留其他階段）：

```bash
# 先查看 commit 歷史
git log --oneline

# 撤銷指定 commit（例如 skills API 修改）
git revert <commit-hash>
```

### 情境 D: 完全廢棄 feature branch

確認修改方向有誤，徹底刪除 feature branch：

```bash
git checkout docai_dev_excel_2026_linux
git branch -D feature/multi-format-support
```

### 情境 E: 回到 tag 標記的精確狀態

使用永久錨點回到修改前的精確狀態：

```bash
git checkout pre-multiformat-support
```

### 情境 F: 修改通過驗證，合併到原始分支

所有測試通過後，將修改正式合入：

```bash
git checkout docai_dev_excel_2026_linux
git merge feature/multi-format-support
```

### 情境 G: 部分合併（Cherry-Pick）

只合併某些 Phase 的修改：

```bash
git checkout docai_dev_excel_2026_linux
git cherry-pick <commit-hash>  # 挑選要合併的 commit
```

## 6. 注意事項

1. **不要直接在 `docai_dev_excel_2026_linux` 上修改** — 所有修改只在 `feature/multi-format-support` 進行
2. **Tag 永遠不會移動** — `pre-multiformat-support` 是永久錨點，即使刪除分支也不受影響
3. **合併前務必測試** — 在 feature branch 上完成所有測試驗證後再合併
4. **Remote 同步** — 目前 tag 和 feature branch 尚未 push 到 remote，如需遠端備份：
   ```bash
   git push origin pre-multiformat-support
   git push origin feature/multi-format-support
   ```
