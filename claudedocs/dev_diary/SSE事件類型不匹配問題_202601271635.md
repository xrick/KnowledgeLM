## 一、SSE 協議基礎

SSE (Server-Sent Events) 每個事件由兩種行組成：

```
event: progress        ← 這是「事件類型」(event type)
data: {"phase":"extraction","percent":10}   ← 這是「資料」(payload)
                       ← 空行 = 一個事件結束
```

瀏覽器（或我們的 ReadableStreamReader）會分別解析這兩行，得到：
- **eventType** = `"progress"`
- **data** = `{phase: "extraction", percent: 10}`

## 二、後端實際發送了什麼

`upload.py:494` 的後端程式碼：

```python
yield create_upload_sse_event(
    "progress",                    #  ← event type 固定是 "progress"
    {
        "phase": "validation",     #  ← 具體階段藏在 data 裡面
        "percent": 5,
        ...
    },
)
```

後端對**所有中間階段**都使用同一個 event type `"progress"`，差異只在 `data.phase`：

```
┌──────────────────────────────────────────────────────┐
│  後端送出的 SSE 事件                                   │
├───────────────┬────────────────┬──────────────────────┤
│ event type    │ data.phase     │ data.percent         │
├───────────────┼────────────────┼──────────────────────┤
│ start         │ —              │ —                    │
│ file_saved    │ —              │ —                    │
│ progress      │ validation     │ 5                    │
│ progress      │ extraction     │ 10                   │
│ progress      │ extraction_complete │ 25              │
│ progress      │ chunking       │ 30                   │
│ checkpoint    │ chunking_complete   │ 35              │
│ progress      │ metadata       │ 40                   │
│ progress      │ embedding      │ 45                   │
│ progress      │ embedding_complete  │ 80              │
│ progress      │ saving         │ 85                   │
│ progress      │ overview       │ 90                   │
│ complete      │ —              │ 100                  │
└───────────────┴────────────────┴──────────────────────┘
```

注意：只有 6 種 **event type**（`start`、`file_saved`、`progress`、`checkpoint`、`complete`、`error`），但有 10+ 種 **data.phase**。

## 三、修正前的 Bug — 兩層混為一層

修正前的前端 `handleSSEEvent(eventType, data)` 是這樣設計的：

```javascript
// ❌ 修正前：把 eventType 當作具體階段名
const phaseProgressMap = {
    extraction_start: 10,      // ← 期望收到 eventType="extraction_start"
    extraction_complete: 35,   // ← 期望收到 eventType="extraction_complete"
    embedding_start: 50,
    ...
};

function handleSSEEvent(eventType, data) {
    const pct = phaseProgressMap[eventType];  // ← 用 eventType 去查
    // ...
}
```

**問題**：前端收到的 `eventType` 永遠是 `"progress"`，不是 `"extraction_start"`。所以 `phaseProgressMap["progress"]` 查不到值 → 走 fallback → 進度條不更新。

用流程圖表示：

```
後端送出: event="progress", data={phase:"extraction", percent:10}
                │
                ▼
前端收到: eventType = "progress"
                │
                ▼
查 phaseProgressMap["progress"] → undefined ❌
                │
                ▼
走 fallback → 只 appendLog，進度條停在 0%
```

## 四、修正後 — 分層處理

修正後的 `handleSSEEvent` 改為**兩層判斷**：

```javascript
// ✅ 修正後：先判斷 eventType，再從 data 取 phase 和 percent
function handleSSEEvent(eventType, data) {

    // 第一層：處理特殊 event type（直接結構性事件）
    if (eventType === "error")      { /* 處理錯誤 */ return; }
    if (eventType === "complete")   { /* 處理完成 */ return; }
    if (eventType === "start")      { /* 處理開始 */ return; }
    if (eventType === "file_saved") { /* 處理檔案接收 */ return; }

    // 第二層：progress/checkpoint → 從 data 取具體資訊
    if (eventType === "progress" || eventType === "checkpoint") {
        const pct   = data.percent;   // ← 直接用後端給的百分比
        const phase = data.phase;     // ← 取具體階段名
        const label = phaseLabels[phase] || data.message;
        updateProgress(pct, label);   // ← 正確更新
        return;
    }
}
```

修正後的流程：

```
後端送出: event="progress", data={phase:"extraction", percent:10}
                │
                ▼
前端收到: eventType = "progress"
                │
                ▼
匹配 if (eventType === "progress") ✅
                │
                ▼
讀取 data.percent = 10, data.phase = "extraction"
                │
                ▼
phaseLabels["extraction"] → "正在提取文字..."
                │
                ▼
updateProgress(10, "正在提取文字...") ✅ 進度條正確更新
```

## 五、核心教訓

這個 bug 的根因是 **SSE 協議的兩層結構與前端的單層假設不匹配**：

| 概念 | SSE 協議 | 修正前前端 | 修正後前端 |
|------|---------|-----------|-----------|
| **Event type** | 訊息分類（progress/error/complete） | ❌ 當成具體階段名 | ✅ 當成分類 |
| **Data payload** | 附帶詳細資訊（phase/percent/message） | ❌ 忽略 phase/percent | ✅ 從 data 取值 |
| **進度百分比** | 由後端在 data.percent 決定 | ❌ 前端 hardcode 查表 | ✅ 直接用後端值 |

修正後的設計更健壯：
- **後端擁有進度百分比的控制權**（single source of truth）
- **前端只負責顯示**，不需要維護一份百分比對照表
- **新增階段時只需改後端**，前端自動顯示 `data.message`
