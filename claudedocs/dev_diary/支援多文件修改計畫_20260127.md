## 修改目標

將 DocAI 系統從「僅支援 PDF」擴展為支援 **PDF、DOCX、PPTX、TXT、MD** 五種格式。
核心策略：**統一使用 Service 層的 config 驗證，移除所有 API Endpoint 層的硬編碼檢查**。

## Reference Scan 結果（2026-01-27 完成）

### 🔴 Critical Bug：返回值類型不一致

| Method | 宣告類型 | 實際返回 | 問題 |
|--------|---------|---------|------|
| `extract_text_from_pdf()` | `-> str` | `(corpus, pages)` tuple | ❌ 類型不符 |
| `extract_text_from_docx()` | `-> str` | `str` | ✅ 正確 |
| `extract_text_from_txt()` | `-> str` | `str` | ✅ 正確 |

**唯一 caller**：`input_data_handle_service.py:544`
```python
text, _pages = self.extract_text(file_content, filename)
```
- PDF → 返回 tuple → ✅ 正常
- DOCX/TXT → 返回 str → ❌ **crash**: `TypeError: cannot unpack non-iterable str object`

**結論**：即使不做多格式支援，這個 bug 也需修復。統一返回 tuple 是正確策略。

### Skills Pipeline SSE 架構分析

**主要 active function**：`process_pdf_for_skill_streaming()`（行 1513-2015）
- 使用 **Producer-Consumer pattern**（background thread 讀 PDF → queue → main loop embedding）
- **14 種 SSE event types**：`start`, `progress`, `checkpoint`, `heartbeat`, `warning`, `info`, `phase_start`, `complete`, `error` 等
- **2 個 caller endpoints**：
  - `upload-source-stream`（行 2028-2118）
  - `upload-source`（行 2121-2229）
- 兩者都用 `EventSourceResponse(generate_sse_events(), ping=15)` 包裝

**SSE 事件格式規範**：
```python
{"event": "event_type_name", "data": "{...json_serialized_payload...}"}
```

##### 2.1.2 新增 `extract_text_from_pptx()` 方法（在 `extract_text_from_txt()` 之後插入）

```python
def extract_text_from_pptx(self, file_content: bytes) -> Tuple[str, int]:
    """Extract text from PPTX file. Returns (corpus, slide_count)."""
    if PptxPresentation is None:
        raise ImportError(
            "python-pptx not installed. Install with: pip install python-pptx"
        )
    
    # 密碼保護偵測：加密的 PPTX 不是有效 zip
    try:
        pptx_file = io.BytesIO(file_content)
        prs = PptxPresentation(pptx_file)
    except Exception as e:
        error_msg = str(e).lower()
        if "encrypted" in error_msg or "password" in error_msg or "bad zip" in error_msg.lower():
            raise ValueError("此檔案受密碼保護，無法處理。請移除密碼保護後重新上傳。")
        raise
    
    slide_texts = []
    for slide_num, slide in enumerate(prs.slides, 1):
        texts = []
        for shape in slide.shapes:
            if shape.has_text_frame:
                for paragraph in shape.text_frame.paragraphs:
                    text = paragraph.text.strip()
                    if text:
                        texts.append(text)
            # 處理表格
            if shape.has_table:
                for row in shape.table.rows:
                    row_text = " | ".join(
                        cell.text.strip() for cell in row.cells if cell.text.strip()
                    )
                    if row_text:
                        texts.append(row_text)
        if texts:
            slide_texts.append(f"[Slide {slide_num}]\n" + "\n".join(texts))
    
    corpus = "\n\n".join(slide_texts)
    if not corpus.strip():
        raise ValueError("PPTX contains no extractable text")
    
    logger.info(f"Extracted {len(corpus)} characters from PPTX ({len(prs.slides)} slides)")
    return corpus, len(prs.slides)
```

##### 2.1.4 修改 `extract_text()` dispatch 方法（行 257-285）

```python
def extract_text(self, file_content: bytes, filename: str) -> Tuple[str, int]:
    """Extract text from file. Returns (corpus, page_count)."""
    file_ext = Path(filename).suffix.lower().lstrip('.')
    
    if file_ext == 'pdf':
        return self.extract_text_from_pdf(file_content)
    elif file_ext == 'docx':
        return self.extract_text_from_docx(file_content)
    elif file_ext == 'pptx':
        return self.extract_text_from_pptx(file_content)
    elif file_ext in ['txt', 'md']:
        return self.extract_text_from_txt(file_content)
    else:
        raise ValueError(f"Unsupported file extension: {file_ext}")
```

##### 3.2.6 新增：`process_document_for_skill_streaming()` 非 PDF SSE Streaming 函數

**設計理念**：
- PDF 繼續使用現有的 `process_pdf_for_skill_streaming()`（Producer-Consumer pattern，已優化）
- 非 PDF 格式使用新函數，一次性提取文字後按 chunk 分批 embedding
- **復用相同 SSE 事件格式**，前端不需要任何 SSE 解析改動

**函數簽名**：
```python
async def process_document_for_skill_streaming(
    file_path: Path,
    file_content: bytes,
    skill_name: str,
    skill_description: str,
    skill_category: str = "General",
    parent_skill_id: str = "root",
    head_id: str = None,
):
    """Non-PDF document processing with SSE streaming progress."""
```

**SSE 事件流程**：
```
start         → {"message": "開始處理文件", "filename": "xxx.docx", ...}
progress      → {"phase": "extraction", "message": "正在提取文字...", "percent": 10}
progress      → {"phase": "extraction_complete", "message": "文字提取完成", "percent": 25, "characters": N}
progress      → {"phase": "chunking", "message": "正在分割文字...", "percent": 30}
checkpoint    → {"phase": "chunking_complete", "message": "分割完成", "total_chunks": N, "percent": 35}
checkpoint    → {"phase": "batch_N", "message": "嵌入批次 N", "batch_num": N, "percent": 35-80}
  (repeat per batch)
progress      → {"phase": "faiss_storage", "message": "正在儲存向量索引...", "percent": 85}
progress      → {"phase": "metadata", "message": "正在儲存元資料...", "percent": 90}
complete      → {"message": "處理完成!", "skill_id": ..., "total_chunks": N, ...}
error         → {"phase": "xxx", "message": "錯誤訊息", ...}  (if failed)
```

**密碼保護偵測**：在 `extract_text()` 階段，如果拋出包含密碼保護訊息的 ValueError，直接 yield error event 並終止：
```python
try:
    text, page_count = input_service.extract_text(file_content, file_path.name)
except ValueError as e:
    if "密碼保護" in str(e):
        yield create_upload_sse_event("error", {
            "phase": "extraction",
            "message": str(e),
            "timestamp": datetime.now().strftime("%H:%M:%S")
        })
        return
    raise
```

**處理流程**：
```
1. 讀取檔案 content（已有）
2. InputDataHandleService.extract_text() → (corpus, page_count)
3. 分 chunk（使用與 PDF 相同的 chunk 策略）
4. Batch embedding（每批 BATCH_SIZE=6 個 chunks）→ SSE checkpoint events
5. FAISS 向量儲存 → SSE progress event
6. SQLite metadata → SSE progress event  
7. 完成 → SSE complete event
```

| Chunking | 25-35% | 文字分割 |
| Batch embedding | 35-80% | 按 chunk 批次計算，動態分配 |
| FAISS storage | 85% | 向量索引儲存 |
| Metadata | 90% | SQLite 元資料 |

## 密碼保護偵測方案

### 偵測機制

| 格式 | 偵測方式 | 說明 |
|------|---------|------|
| PDF | `PyPDF2.PdfReader.is_encrypted` | PyPDF2 內建屬性 |
| DOCX | `try/except BadZipFile` | 加密 DOCX 不是有效 zip |
| PPTX | `try/except BadZipFile` | 加密 PPTX 不是有效 zip |
| TXT/MD | 不適用 | 純文字無加密概念 |

### 統一錯誤訊息

```
此檔案受密碼保護，無法處理。請移除密碼保護後重新上傳。
```

### 偵測位置

在 `InputDataHandleService` 各 extract 方法的**最早階段**進行偵測，確保 fail-fast。

對 SSE streaming 流程，密碼保護會觸發 `error` event：
```json
{
    "event": "error",
    "data": "{\"phase\": \"extraction\", \"message\": \"此檔案受密碼保護，無法處理。請移除密碼保護後重新上傳。\"}"
}
```

## 影響分析

- **影響範圍**: File-Based 上傳、Skills 上傳、前端檔案選取、Provider 來源名稱
- **向後相容**: ✅ 是 — PDF 處理流程完全不變，舊檔案保留在 `uploadfiles/pdf/`
- **風險**: 🟡 中 — 新格式提取需測試邊界情況（中文 DOCX、大型 PPTX、加密檔案等）
- **性能影響**: 低 — 提取邏輯是一次性操作
- **前端 SSE 影響**: 無 — 新函數復用相同 SSE 事件格式

## 回滾方案

1. 將 `ALLOWED_EXTENSIONS` 改回 `["pdf"]`
2. 恢復 API Endpoint 層的硬編碼檢查
3. 前端 accept 改回 `.pdf`
4. Provider 的 `Path().stem` 修改不需回滾（對 PDF 也正確）

所有修改都是加法性質，不影響現有 PDF 功能，回滾僅需恢復配置。
新增的 `process_document_for_skill_streaming()` 函數不會被 PDF 流程調用，回滾時可保留不刪。
