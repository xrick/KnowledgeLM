### 🔴 Critical Bug 修復

**問題**：`extract_text()` 的唯一 caller（行 543）使用 `text, _pages = self.extract_text(...)` tuple unpacking，但 DOCX/TXT 返回 `str` 導致 crash。

**修復**：統一所有 extract 方法返回 `Tuple[str, int]`，消除 `TypeError: cannot unpack non-iterable str object`。

### 新增函數：`process_document_for_skill_streaming()`

**用途**：處理非 PDF 文件（DOCX, PPTX, TXT, MD）的 SSE streaming pipeline

**設計決策**：
- 復用相同 SSE event 格式 → 前端不需改動 SSE 解析
- 復用相同 embedding + FAISS + metadata 邏輯
- 使用 `InputDataHandleService.extract_text()` 進行文字提取
- 使用 `RecursiveCharacterTextSplitter` 進行 chunking（chunk_size=1000）
- 密碼保護偵測：捕獲 `ValueError` 中的 `密碼保護` 關鍵字

**SSE 進度百分比映射**：

| Phase | % | 說明 |
|-------|---|------|
| Start | 5% | 開始處理 |
| Text extraction | 10-25% | 一次性提取全部文字 |
| Chunking | 25-35% | 文字分割 |
| Batch embedding | 35-80% | 按 chunk 批次計算 |
| FAISS storage | 85% | 向量索引儲存 |
| Metadata | 90-95% | SQLite 元資料 |
| Complete | 100% | 完成 |

### 格式路由邏輯

```python
file_ext = Path(file.filename).suffix.lower().lstrip('.')
if file_ext == 'pdf':
    # Producer-Consumer pipeline（現有）
    async for event in process_pdf_for_skill_streaming(...):
        yield event
else:
    # Unified document pipeline（新增）
    async for event in process_document_for_skill_streaming(...):
        yield event
```
