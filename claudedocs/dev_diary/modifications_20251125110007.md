## 1. app/api/v1/endpoints/chat.py

### 修改位置
Lines 271-294

### 問題描述
當用戶勾選 3-4 個檔案並請求摘要時，只有 1-2 個檔案出現在回應中。

**根本原因**:
- `get_multiple_overviews()` 方法只回傳有非空 overview 的檔案
- 完全沒有 overview 記錄的檔案不會出現在 `overviews` dict 中
- 原本的邏輯只檢查 dict 中已存在的檔案，無法偵測到完全缺失的檔案

### 第一次嘗試（邏輯錯誤）
```python
# ❌ 錯誤的邏輯
for file_id, overview in overviews.items():
    if overview and overview.strip():
        files_with_overview.append(file_id)
    else:
        # 這個 else 永遠不會執行，因為 overviews.items()
        # 已經過濾掉空的 overview
        files_without_overview.append(file_id)
```

**問題**: `overviews.items()` 只包含有 overview 的檔案，所以 `else` 分支永遠不會執行。完全缺失的檔案無法被偵測到。

### 正確的修復方案
```python
# ✅ 正確的邏輯
# Separate files with valid overviews from those without
# IMPORTANT: Compare against request.file_ids to find files missing from overviews dict
files_with_overview = []
files_without_overview = []

# First, check files that ARE in overviews dict
for file_id, overview in overviews.items():
    if overview and overview.strip():
        files_with_overview.append(file_id)
        context_chunks.append({
            "content": overview,
            "metadata": {"file_id": file_id, "source": "overview_shortcut"}
        })
    else:
        files_without_overview.append(file_id)

# Second, find files that are NOT in overviews dict at all (completely missing)
overviews_keys = set(overviews.keys())
for file_id in request.file_ids:
    if file_id not in overviews_keys:
        files_without_overview.append(file_id)
        logger.warning(f"[SHORTCUT] File {file_id} has no overview record at all")

logger.info(f"[SHORTCUT] {len(files_with_overview)} files have valid overviews, {len(files_without_overview)} need FAISS fallback")
```

### 修復效果
- ✅ 偵測到完全沒有 overview 記錄的檔案
- ✅ 為沒有 overview 的檔案啟用 FAISS fallback
- ✅ 所有勾選的檔案都會出現在摘要結果中

### 技術要點
1. **兩階段檢查**: 先檢查 dict 中的檔案，再比對 `request.file_ids` 找出缺失的檔案
2. **保護機制**: 使用 `set(overviews.keys())` 提升查詢效率
3. **日誌記錄**: 區分「overview 為空」和「完全沒有 overview 記錄」兩種情況

### 保護機制
```python
def detect_multi_file_summary_intent(self, query: str, file_count: int) -> bool:
    if file_count < 2:
        return False  # ← 保護單一檔案查詢不受影響

    is_summary = self.detect_summary_intent(query)
    is_multi_file = self.detect_multi_file_intent(query)

    return is_summary or is_multi_file
```

**關鍵保護**: `file_count < 2` 確保單一檔案查詢不會誤觸發多文件模式，即使查詢包含「內容」等關鍵字。

### 影響分析
**問題**: 新增「內容」關鍵字會不會影響單一檔案查詢？
例如：「解釋 bitnet.cpp 的內容」

**答案**: ✅ 不會影響

**原因**:
1. 單一檔案查詢時 `file_count = 1`
2. `detect_multi_file_summary_intent()` 會在開頭檢查 `if file_count < 2: return False`
3. 即使查詢包含「內容」關鍵字，也會因為檔案數量不足而回傳 False
4. 系統會使用標準的單一檔案查詢流程

- 例如: `MAX_TOKENS = 1500`, `OVERVIEW_MAX_CHARS = 3000`
- 需評估生成時間與品質的權衡

## 技術概念說明

### MAX_TOKENS vs OVERVIEW_MAX_CHARS

**MAX_TOKENS**:
- LLM 生成時的輸出限制（以 token 為單位）
- 控制 LLM 生成階段的長度
- 中文約 1-2 字元/token

**OVERVIEW_MAX_CHARS**:
- 後處理階段的截斷限制（以字元為單位）
- 在生成完成後進行字元數截斷
- 確保儲存的 overview 不超過設定長度

**關係**:
1. LLM 先根據 MAX_TOKENS 生成內容
2. 生成完成後根據 OVERVIEW_MAX_CHARS 截斷
3. 兩者需要協調才能發揮效果
